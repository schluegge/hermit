## Contradiction / falsification pass

1. **Schema inference:** TFDV can infer an initial schema, but no source says the inferred schema is automatically the correct domain policy. It is treated as bootstrap evidence only.
2. **Windows:** older TFDV release history deprecated Windows support; checked 1.21.0 notes do not establish current Windows support. Current 1.21.0 Windows compatibility remains unresolved.
3. **Feature store boundary:** Feast explicitly relies on external transformation infrastructure in important cases and does not perform model deployment. It is not represented as an all-in-one ML platform.
4. **Offline/online semantics:** Feast's online store retains latest entity values, while historical/point-in-time training retrieval belongs to the offline-store path. They are not conflated.
5. **Orchestration correctness:** KFP/Airflow task success is execution evidence, not data/model correctness evidence.
6. **KFP/Airflow equivalence:** KFP is ML/Kubernetes-oriented with artifact/metadata semantics; Airflow is a general batch workflow platform. No universal preference is asserted.
7. **KFP upgrade:** current metadata docs state the KFP 2.15 metadata index migration does not support rollback; no claim of transparent/reversible upgrade is made.
8. **Airflow streaming:** Airflow's current docs explicitly call it batch-oriented. It is not generalized into a continuously streaming processor.
9. **AI authority:** no checked source proves a specific AI system should autonomously promote production data/models. AI assistance remains behind deterministic validation/evaluation/approval gates.
