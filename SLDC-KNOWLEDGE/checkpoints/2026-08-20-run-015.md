## Evidence added

### Microsoft SQL Server / Azure SQL

Source type: official Microsoft documentation.

Verified 2026-08-20:

- supported index create/rebuild operations can run with `ONLINE = ON`, but online support has operation/type/version/edition restrictions;
- online operations can still require temporary/data-file and version-store capacity and can fail because of deadlocks, uniqueness conflicts, locks, or unsupported index types;
- `WAIT_AT_LOW_PRIORITY` exposes explicit behavior for lock waits, including self-abort or terminating blockers when configured and authorized;
- supported index create/rebuild operations can be made resumable, paused and resumed, including after interruption/failover; paused operations still consume storage and can affect update-heavy DML throughput;
- `ALTER COLUMN ... WITH (ONLINE = ON)` exists for supported SQL Server/Azure SQL versions;
- SQL Server 2022+ supports resumable online addition of `PRIMARY KEY` and `UNIQUE` constraints, but not foreign keys;
- generic `ALTER TABLE` retains schema-modification locking semantics, so SQL Server online support is not a universal no-lock DDL mode.

Sources:

- https://learn.microsoft.com/en-us/sql/relational-databases/indexes/guidelines-for-online-index-operations?view=sql-server-ver17
- https://learn.microsoft.com/en-us/sql/t-sql/statements/alter-table-transact-sql?view=sql-server-ver17
- https://learn.microsoft.com/en-us/sql/relational-databases/security/resumable-add-table-constraints?view=sql-server-ver17

### Oracle AI Database 26

Source type: official Oracle documentation.

Verified 2026-08-20:

- `DBMS_REDEFINITION` provides online table redefinition;
- the multi-step path uses candidate checking, an interim table, synchronization/dependent-object handling, and a finalization step;
- DML is available for most of the operation, while `FINISH_REDEF_TABLE` requires a short exclusive lock window; `dml_lock_timeout` can bound waiting for the required locks;
- `V$ONLINE_REDEF` and `DBA_REDEFINITION_STATUS` expose runtime/status evidence, including restartability/errors;
- failed online redefinition can often be corrected and restarted from the last stopped point;
- optional rollback must be enabled explicitly during `START_REDEF_TABLE`; when enabled Oracle can return the table to the pre-redefinition definition while preserving subsequent DML changes;
- that rollback mechanism is scoped to Oracle online table redefinition and is not evidence that arbitrary application side effects or every schema migration are reversible.

Sources:

- https://docs.oracle.com/en/database/oracle/oracle-database/26/admin/managing-tables.html
- https://docs.oracle.com/en/database/oracle/oracle-database/26/arpls/DBMS_REDEFINITION.html
- https://docs.oracle.com/en/database/oracle/oracle-database/26/refrn/DBA_REDEFINITION_STATUS.html
- https://docs.oracle.com/en/database/oracle/oracle-database/26/refrn/V-ONLINE_REDEF.html
