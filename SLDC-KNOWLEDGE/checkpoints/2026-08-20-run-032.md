## New independently supported evidence

### MCUboot 2.4.0

Source type: maintainer repository/documentation.  
Verified: 2026-08-20.

- Maintainer releases identify MCUboot 2.4.0 as current stable.
- Test-swap lifecycle can boot a candidate image and revert on a later reset unless firmware confirms it.
- Downgrade prevention is separate from test-swap recovery.
- Hardware rollback protection uses an image security counter compared with trusted non-volatile platform state.
- Security counter and ordinary image version are intentionally separate concepts.

Sources:
- https://github.com/mcu-tools/mcuboot/releases
- https://docs.mcuboot.com/design.html
- https://github.com/mcu-tools/mcuboot

### ESP-IDF current ESP32 anti-rollback

Source type: official vendor documentation.  
Verified: 2026-08-20.

- Bootloader anti-rollback compares application `security_version` with an eFuse value.
- Candidate firmware must be at or above the device security floor.
- OTA rollback and anti-rollback can coexist only within the security-version boundary.
- The documented ESP32 eFuse field is finite and irreversible; current OTA documentation describes a 32-bit security-version budget.
- Espressif explicitly documents the reason signature validity is insufficient: an older legitimately signed image can still contain revoked security behavior/credentials.

Sources:
- https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-reference/system/ota.html
- https://docs.espressif.com/projects/esp-idf/en/latest/esp32/security/security.html
- https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-reference/system/efuse.html

### Uptane 2.1.0

Source type: official standard and deployment guidance.  
Verified: 2026-08-20.

- Official version index identifies Uptane Standard 2.1.0 as latest released Standard.
- Threat model covers freeze, rollback, partial-bundle, mix-and-match and arbitrary-software attacks.
- Deployment guidance separates metadata-version rollback prevention from per-image release-counter rollback prevention.
- Intentional software rollback is treated as an exceptional security-sensitive operation.
- Multi-ECU bundle installation and consistency are distinct from per-image signature validity; two-phase-commit-style coordination is discussed only with explicit assumptions and limits.
- Packaged-software/build-system compromise remains outside Uptane's core scope and therefore stays in the repository's separate supply-chain evidence plane.

Sources:
- https://uptane.org/docs/latest/all-versions
- https://uptane.org/docs/latest/standard/uptane-standard
- https://uptane.org/docs/2.1.0/deployment/best-practices
