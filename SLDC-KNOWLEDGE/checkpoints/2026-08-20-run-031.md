## New independently supported evidence

### openSUSE transactional-update

Source type: maintainer repository / upstream project documentation.  
Verified: 2026-08-20.

- Upstream defines transactional-update as applying OS changes to a candidate snapshot while the running system remains unchanged.
- Failed update transactions can be discarded instead of becoming the active system state.
- The project explicitly documents openSUSE MicroOS and SUSE Linux Enterprise Micro among the systems using this mechanism.
- Upstream NEWS lists version 6.1.3 dated 2026-07-20.
- Upstream documents a mutable-state boundary: `/var` cannot simply be treated as part of the atomic root update.

Sources:
- https://github.com/openSUSE/transactional-update
- https://github.com/openSUSE/transactional-update/blob/master/NEWS

### openSUSE health-checker

Source type: maintainer repository; corroborated by SUSE vendor documentation.  
Verified: 2026-08-20.

- `health-checker` is called by systemd during boot and executes plugins that test services/conditions.
- Packaged checks and administrator-provided checks are supported through separate plugin directories.
- On BLS paths (including systemd-boot/grub2-bls), new snapshot entries use automatic boot assessment with retry counters; successful health checks bless the boot, while failed checks reboot into the next available snapshot.
- The maintainer documentation states `/etc/kernel/tries` defaults to 3.
- On the documented legacy-GRUB path, failure on a new snapshot triggers rollback to the last known working Btrfs root snapshot.
- A previously successful snapshot is treated differently: one retry is attempted, then checked services are stopped and operator intervention is allowed rather than entering an endless reboot loop.

Sources:
- https://github.com/openSUSE/health-checker
- https://documentation.suse.com/smart/micro-clouds/html/SLE-Micro-5.5-admin/index.html

### Data/state boundary

Source type: project documentation.  
Verified: 2026-08-20.

openSUSE/SUSE guidance explicitly prevents treating OS snapshot rollback as third-party application-data rollback. This preserves the baseline rule that root-filesystem recovery is not equivalent to database, external-service, peripheral, or business-state recovery.

Sources:
- https://en.opensuse.org/openSUSE:Packaging_Requirements_for_Atomic_and_Image_Update
- https://en.opensuse.org/SDB:System_upgrade_of_LeapMicro
