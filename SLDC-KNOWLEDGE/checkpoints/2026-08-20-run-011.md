## Sources inspected

### Apple — official App Store Connect / App Store Connect API documentation

- Phased release: https://developer.apple.com/help/app-store-connect/update-your-app/release-a-version-update-in-phases
- `PhasedReleaseState`: https://developer.apple.com/documentation/appstoreconnectapi/phasedreleasestate

Verified:

- version updates can be phased over seven days at 1%, 2%, 5%, 10%, 20%, 50%, 100%;
- phased release can be paused for a cumulative total of up to 30 days;
- users can manually download the version during phased release;
- pause therefore does not establish universal exposure stop or installed-device rollback.

### Google Play — official Play Console documentation

- Staged rollouts: https://support.google.com/googleplay/android-developer/answer/6346149
- Halting a fully rolled-out release: https://support.google.com/googleplay/android-developer/answer/16285429

Verified:

- staged rollout percentage is operator-selected and does not automatically increase;
- staged rollout can be halted; users who already received the version remain on it;
- a fully rolled-out release can also be halted on eligible tracks and a previous live release can again be served to new/eligible users;
- no forced downgrade of devices already running the halted release is claimed.

### AWS IoT Jobs — official developer/API documentation

- Overview: https://docs.aws.amazon.com/iot/latest/developerguide/jobs-what-is.html
- Job rollout/abort configuration: https://docs.aws.amazon.com/iot/latest/developerguide/jobs-configurations-details.html
- `ExponentialRolloutRate`: https://docs.aws.amazon.com/iot/latest/apireference/API_ExponentialRolloutRate.html

Verified:

- jobs target one or more devices for remote operations;
- constant and exponential rollout-rate controls exist;
- configured failure criteria can cancel/abort further rollout;
- this is rollout containment evidence, not proof of universal device-side rollback.

### Microsoft Azure Device Update for IoT Hub — official Microsoft Learn documentation

- Overview: https://learn.microsoft.com/en-us/azure/iot-hub-device-update/understand-device-update
- Deployment model: https://learn.microsoft.com/en-us/azure/iot-hub-device-update/device-update-deployments
- Device groups: https://learn.microsoft.com/en-us/azure/iot-hub-device-update/device-update-groups
- Deployment procedure/API/CLI semantics: https://learn.microsoft.com/en-us/azure/iot-hub-device-update/deploy-update

Verified:

- OTA deployments target device groups and report deployment/device status;
- groups/scheduling support staged flighting;
- automatic rollback policy can be configured with failed-count / failed-percentage criteria and an explicit fallback update version;
- rollback-target support does not prove arbitrary application/data/hardware state restoration.

Caveat: some Microsoft Learn deployment pages surfaced an authorization banner while still returning relevant official-page content. This was recorded rather than hidden.
