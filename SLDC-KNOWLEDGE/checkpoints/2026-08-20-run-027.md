## Primary/current evidence inspected

### Flatpak

Official Flatpak documentation:

- https://docs.flatpak.org/en/latest/using-flatpak.html
- https://docs.flatpak.org/en/latest/repositories.html
- https://docs.flatpak.org/en/latest/tips-and-tricks.html
- https://docs.flatpak.org/en/latest/flatpak-devel.html
- https://docs.flatpak.org/en/latest/flatpak-builder.html

Verified claims used:

- installed apps/runtimes update from remotes;
- repositories retain versioned revisions and can publish deltas;
- repository metadata can carry GPG trust material and signed commits are supported/recommended;
- `flatpak update --commit=<COMMIT>` can deploy an older commit;
- `flatpak mask` can prevent updates/installation for matching refs;
- `flatpak history` records changes;
- stable/development variants should use distinct application IDs for safe parallel installation.

### Snap / snapd

Current Canonical documentation:

- https://snapcraft.io/docs/how-to-guides/manage-snaps/manage-updates/
- https://snapcraft.io/docs/reference/development/supported-snap-hooks/
- https://snapcraft.io/docs/explanation/how-snaps-work/transactional-updates/
- https://snapcraft.io/docs/explanation/security/security-policies/
- https://snapcraft.io/docs/reference/interfaces/snap-refresh-control-interface/

Material source freshness: the update-management page was last updated 2026-06-08 in the retrieved official documentation.

Verified claims used:

- published snaps automatically refresh; default check cadence is four times daily according to current docs;
- holds/schedules can postpone refreshes with documented distinctions between automatic/general/targeted refresh behavior;
- `snap revert` restores a prior retained revision and revision-specific snap configuration/system data, but ordinary/common user data is not generally reverted;
- `pre-refresh`/`post-refresh` hooks exist; official docs say a failing `post-refresh` rolls back the refresh and restores original snap state;
- `--transaction=all-snaps` provides all-or-nothing multi-snap update behavior;
- gate-auto-refresh / snap-refresh-control remains documented as experimental/under development and privileged where applicable.

### AppImage / AppImageUpdate

Official AppImage documentation plus maintainer repository:

- https://docs.appimage.org/packaging-guide/optional/updates.html
- https://docs.appimage.org/packaging-guide/optional/signatures.html
- https://docs.appimage.org/packaging-guide/distribution.html
- https://github.com/AppImageCommunity/AppImageUpdate

Verified claims used:

- update information can be embedded into an AppImage and zsync metadata can support delta updates;
- update functionality can be external, bundled, or integrated through `libappimageupdate`;
- AppImages can carry embedded GPG signatures, but displaying a signature is not validation and validation requires independent tooling;
- the current AppImageUpdate maintainer README explicitly calls the implementation beta-level code with limited real-world experience.
