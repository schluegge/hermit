## Research additions

### LLVM libFuzzer — C/C++ representative

Verified from current LLVM documentation:

- libFuzzer is an in-process, coverage-guided evolutionary fuzzing engine using `LLVMFuzzerTestOneInput` targets and SanitizerCoverage feedback.
- It integrates through Clang `-fsanitize=fuzzer` and can be combined with ASan/UBSan and other sanitizers.
- Corpus replay, crash artifacts, corpus minimization and regression-style replay are documented.
- Targets should be fast and deterministic and should tolerate malformed inputs.
- Current lifecycle caveat: original authors stopped active feature work and moved to Centipede; important bugs remain supported, but major new features/code review should not be expected.
- libFuzzer requires a matching Clang version.

Primary sources, verified 2026-08-20:

- https://llvm.org/docs/LibFuzzer.html
- https://clang.llvm.org/docs/SanitizerCoverage.html

### Go native fuzzing — standard-toolchain representative

Verified from official Go documentation:

- Native fuzzing is part of the standard Go toolchain since Go 1.18.
- Fuzz tests use `testing.F`, live in `_test.go`, and run through `go test`.
- `go test` without fuzz mode replays seeds/known failures; `go test -fuzz=...` performs coverage-guided exploration.
- Failing inputs are written to the seed corpus and subsequently replayed by ordinary tests, creating a direct discovery-to-regression path.
- `-fuzztime` bounds execution and `-parallel` controls fuzzing workers.
- Current coverage-instrumented fuzzing is documented for AMD64 and ARM64; no broader architecture claim was made.

Primary sources, verified 2026-08-20:

- https://go.dev/doc/security/fuzz/
- https://go.dev/doc/tutorial/fuzz

### Rust `cargo-fuzz` — ecosystem representative

Verified from Rust Fuzz Book and maintainer repository:

- `cargo-fuzz` is the recommended Rust fuzz-testing integration and currently wraps libFuzzer through `libfuzzer-sys` according to the maintained Fuzz Book.
- Current latest maintainer release observed: `cargo-fuzz` 0.13.2, released 2026-06-09.
- The current changelog records a `--fuzz-engine` option for `cargo fuzz init`; this was not interpreted as proof of broadly supported alternative engines because the current Fuzz Book still describes libFuzzer as the supported engine.
- Workflow support includes target generation/run, failing-input minimization, corpus minimization, coverage generation and bounded CI smoke fuzzing with artifact retention.
- Nightly Rust is required in current maintainer documentation because sanitizer-related compiler flags are unstable.

Primary sources, verified 2026-08-20:

- https://rust-fuzz.github.io/book/cargo-fuzz.html
- https://rust-fuzz.github.io/book/cargo-fuzz/setup.html
- https://rust-fuzz.github.io/book/cargo-fuzz/ci.html
- https://github.com/rust-fuzz/cargo-fuzz
- https://github.com/rust-fuzz/cargo-fuzz/blob/main/CHANGELOG.md
- https://github.com/rust-fuzz/cargo-fuzz/releases

No independent current reproduction or maintainer clarification was available in this run. Therefore current Windows support for the documented `cargo-fuzz` baseline remains **unresolved** and is explicitly recorded as such.

### Jazzer — JVM representative

Verified from current maintainer repository/documentation:

- Jazzer is a coverage-guided in-process JVM fuzzer based on libFuzzer concepts.
- Current documented platforms include Linux x86_64/arm64, macOS 12+ x86_64/arm64 and Windows x86_64.
- Recommended integration uses `jazzer-junit` with JUnit 5.9.0+ and supports Maven, Gradle and Bazel.
- JUnit integration distinguishes regression mode (default replay of stored crashing inputs) from fuzzing mode (`JAZZER_FUZZ=1`) that mutates inputs to find new coverage/failures.
- New-coverage corpus and crash inputs are persisted for later replay.
- Current latest release observed: Jazzer v0.30.0.

Primary sources, verified 2026-08-20:

- https://github.com/CodeIntelligenceTesting/jazzer
- https://github.com/CodeIntelligenceTesting/jazzer/blob/main/docs/arguments-and-configuration-options.md
- https://github.com/CodeIntelligenceTesting/jazzer/releases
