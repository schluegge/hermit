## Sources inspected

### LaunchDarkly — official documentation

- Kill switch flags: https://launchdarkly.com/docs/home/flags/killswitch
- Release flags: https://launchdarkly.com/docs/home/flags/release
- Progressive rollouts: https://launchdarkly.com/docs/home/releases/progressive-rollouts
- Creating/managing progressive rollouts: https://launchdarkly.com/docs/home/releases/create-progressive-rollouts
- Guarded rollouts: https://launchdarkly.com/docs/home/releases/guarded-rollouts
- Managing guarded rollouts: https://launchdarkly.com/docs/home/releases/managing-guarded-rollouts

Verified distinctions preserved:

- release flags and kill-switch flags have different lifecycle roles;
- ordinary progressive rollouts do not provide the metric monitoring of guarded rollouts;
- guarded rollouts can use selected metrics and automatic rollback;
- rollback scope is not universal (for example dependent flags are not automatically reverted when a prerequisite flag is rolled back).

### Redgate Flyway — official product documentation

- Migrations: https://documentation.red-gate.com/flyway/flyway-concepts/migrations
- `migrate`: https://documentation.red-gate.com/flyway/reference/commands/migrate
- `validate`: https://documentation.red-gate.com/flyway/reference/commands/validate
- `repair`: https://documentation.red-gate.com/flyway/reference/commands/repair
- Undo migrations: https://documentation.red-gate.com/flyway/flyway-concepts/migrations/undo-migrations

Verified distinctions preserved:

- migration files are version-controlled incremental database changes;
- `validate` compares applied migration metadata/checksums against available migrations;
- `repair` repairs schema-history metadata and can require manual cleanup after failed migrations;
- optional undo migrations do not make destructive changes universally safe to reverse.

### AWS CodeDeploy — official documentation

- Deployment configurations: https://docs.aws.amazon.com/codedeploy/latest/userguide/deployment-configurations.html
- Deployments: https://docs.aws.amazon.com/codedeploy/latest/userguide/deployments.html
- Rollback/redeploy: https://docs.aws.amazon.com/codedeploy/latest/userguide/deployments-rollback-and-redeploy.html
- Advanced deployment-group options: https://docs.aws.amazon.com/codedeploy/latest/userguide/deployment-groups-configure-advanced-options.html

Verified distinctions preserved:

- EC2/on-premises, Lambda, and ECS use different deployment semantics;
- Lambda/ECS support canary, linear, and all-at-once traffic shifting;
- automatic rollback can be triggered by deployment failure or configured monitoring thresholds;
- rollback can be implemented as a new deployment/redeployment and does not automatically revert arbitrary deployment-script side effects.
