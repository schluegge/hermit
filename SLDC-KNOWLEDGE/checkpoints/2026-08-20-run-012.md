## Sources inspected

### Google SRE Workbook — primary publication

- Example Error Budget Policy: https://sre.google/workbook/error-budget-policy/
- Implementing SLOs: https://sre.google/workbook/implementing-slos/

Verified:

- error-budget policy can explicitly halt releases after budget exhaustion;
- production freeze is a policy response to reliability state;
- policy thresholds/exceptions require stakeholder agreement;
- Google's concrete example thresholds/windows are illustrative, not universal standards.

### OpenSLO — primary specification/maintainer repositories

- Specification: https://github.com/OpenSLO/OpenSLO
- CLI: https://github.com/OpenSLO/oslo

Verified:

- `openslo/v1` defines vendor-neutral SLO/SLI/alert-policy objects;
- burn-rate alert conditions are representable;
- `oslo validate` validates OpenSLO YAML/JSON and `oslo fmt` formats it;
- schema validation does not prove monitoring-backend query semantics.

### Grafana — official vendor documentation

- Grafana SLO: https://grafana.com/docs/plugins/grafana-slo-app/latest/
- Burn-rate notifications: https://grafana.com/docs/plugins/grafana-slo-app/latest/set-up/configure-burn-rate-notifications/
- Troubleshooting: https://grafana.com/docs/grafana-cloud/alerting-and-irm/slo/troubleshooting/
- Maintenance windows: https://grafana.com/docs/grafana-cloud/observe-and-act/alert-and-measure-reliability/slo/maintenance-windows/

Verified:

- SLO targets, error budgets and burn-rate alerting are supported;
- current plugin docs surfaced `v1.94.0 (latest)` during verification;
- newly created SLO recording rules do not backfill historical data, so some full-window panels are incomplete until the window elapses;
- maintenance windows omit generated SLI samples and do not backfill them later;
- therefore initialization/no-data/maintenance semantics are decision-relevant for any release gate consuming Grafana SLO state.

### Harness SRM — official vendor documentation

- SLO-Driven Governance: https://developer.harness.io/docs/service-reliability-management/slo-driven-deployment-governance/
- Automated Deployment Rollbacks: https://developer.harness.io/docs/service-reliability-management/manage-slo/automated-deployment-rollback/
- Reset error budget: https://developer.harness.io/docs/service-reliability-management/manage-slo/reset-error-budget/

Verified:

- OPA/Rego governance can prevent pipeline deployment when SLO conditions or remaining error-budget conditions fail;
- governance can require SLO configuration for monitored services;
- SLO error-budget policy can trigger automated rollback of a recent deployment within a configured rollback window;
- error-budget reset has role/audit semantics and is not evidence that reliability improved;
- inspected reset page limits reset support to Calendar-period SLOs.

### Datadog — official vendor documentation

- SLO Alerts: https://docs.datadoghq.com/monitors/types/slo/
- Error Budget Alerts: https://docs.datadoghq.com/service_level_objectives/error_budget/
- Burn Rate Alerts: https://docs.datadoghq.com/service_level_objectives/burn_rate/
- Deployment Gates: https://docs.datadoghq.com/deployment_gates/
- Deployment Gates setup: https://docs.datadoghq.com/deployment_gates/setup/

Verified independently:

- SLO error-budget/burn-rate alerts exist and SLO alert is a monitor type;
- Deployment Gates are currently marked Preview;
- Deployment Gates can evaluate monitor/APM rules and asynchronously resolve to pass/fail;
- monitor rules fail on matching monitor `ALERT` or `NO_DATA` states.

Unresolved rather than inferred:

- inspected documentation did not explicitly confirm that every SLO Alert monitor is supported as a Deployment Gate monitor-rule target or provide an SLO-alert-to-gate recipe;
- therefore direct `Datadog SLO -> Deployment Gate` compatibility remains `unresolved`.

### Harness AI SRE — official vendor documentation

- Harness SLO integration: https://developer.harness.io/3k-docs/ai-sre/alerts/alerts/integrations/monitoring/harness-slo/
- AI SRE overview: https://developer.harness.io/docs/ai-sre/get-started/overview/
- RCA Change Agent: https://developer.harness.io/3k-docs/ai-sre/ai-agent/rca-change-agent/

Verified:

- Harness SLO budget/burn-rate notifications can feed AI SRE via a direct webhook integration;
- AI SRE can route/enrich alerts and associate/trigger response workflows;
- RCA Change Agent analyzes recent deployments, pull requests and change events to produce confidence-scored root-cause theories;
- this supports AI-assisted investigation/response, not autonomous replacement of deterministic release policy.
