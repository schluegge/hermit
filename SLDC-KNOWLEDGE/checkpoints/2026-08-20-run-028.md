## Contradiction / deduplication pass

Preserved these distinctions:

- APT signed Release metadata ≠ RPM package signature verification ≠ Pacman `SigLevel` semantics.
- DNF5 transaction-history rollback ≠ SUSE filesystem/root snapshot rollback.
- package downgrade/version selection ≠ application or user-data rollback.
- package metadata/file verification ≠ functional application health.
- holds/exclusions prevent or constrain future changes; they do not undo prior changes.
- SUSE snapshot rollback is conditional on documented filesystem/snapshot scope; it is not generalized to all Zypper systems.

No existing baseline file was duplicated: Flatpak/Snap/AppImage remain in `linux-desktop-updates.md`; the new file is specifically for distribution-native package stacks.

## Unresolved

- Universal APT downgrade/reversal semantics are not claimed; repository/version availability and dependency solvability vary.
- Effective DNF5 signature policy on a specific distribution installation must be inspected rather than inferred from upstream defaults.
- SUSE rollback beyond documented supported root/subvolume configurations remains unverified.
- Pacman older-artifact availability depends on repository/cache state and must be checked live.
- Cross-manager atomicity, scriptlet failure, reboot, service restart, and application-data semantics are intentionally not normalized.
- Immutable/transactional OS image systems beyond the bounded SUSE evidence remain a separate open frontier.
