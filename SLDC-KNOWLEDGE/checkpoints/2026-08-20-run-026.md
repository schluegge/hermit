## Research question

Establish a language-agnostic baseline for transactional lakehouse table-history semantics, with current representative implementations for Apache Iceberg, Delta Lake, and Apache Hudi. Preserve format-specific historical identity, time-travel, retention/cleanup, incremental/change-read, and automation boundaries without claiming cross-format equivalence or performance superiority.

## Authoritative evidence inspected

### Apache Iceberg

1. Official documentation — Branching and Tagging: https://iceberg.apache.org/docs/latest/branching/
   - snapshot log basis;
   - branch/tag references and independent retention;
   - WAP/audit-branch validation + fast-forward workflow.
2. Official documentation — Spark Queries: https://iceberg.apache.org/docs/latest/spark-queries/
   - `TIMESTAMP AS OF` / `VERSION AS OF`;
   - snapshot ID, branch and tag access;
   - schema-selection differences for concrete snapshots versus branch heads.
3. Official specification: https://iceberg.apache.org/spec/
   - snapshot-reference object and point-in-time read semantics.
4. Official project release record: https://github.com/apache/iceberg/blob/main/site/docs/releases.md
   - Iceberg 1.11.0 released 2026-05-19; current release observed during this run.

### Delta Lake

5. Official documentation — batch reads/writes: https://docs.delta.io/delta-batch/
   - transaction log as source of truth;
   - version/timestamp time travel;
   - default log retention 30 days and deleted-file retention 7 days;
   - timestamp-copy caveat;
   - history readability requires both log and backing data files.
6. Official documentation — utility commands: https://docs.delta.io/delta-utility/
   - `VACUUM`, `DRY RUN`, retention and concurrent-reader/stream safety caveats;
   - time travel older than retained files is lost after cleanup.
7. Maintainer release page: https://github.com/delta-io/delta/releases
   - Delta Lake 4.3.1 marked latest, released 2026-07-08.

### Apache Hudi

8. Official documentation — Spark Quick Start: https://hudi.apache.org/docs/quick-start-guide/
   - time travel with `as.of.instant` / SQL `TIMESTAMP AS OF`;
   - incremental queries over commit ranges.
9. Official documentation — Cleaning: https://hudi.apache.org/docs/cleaning/
   - MVCC file history;
   - default automatic cleaning;
   - `KEEP_LATEST_COMMITS`, `KEEP_LATEST_FILE_VERSIONS`, `KEEP_LATEST_BY_HOURS`;
   - retention must protect long-running readers and incremental-history windows.
10. Official documentation — SQL Queries: https://hudi.apache.org/docs/next/sql_queries/
    - time travel and CDC query semantics.
11. Maintainer release page: https://github.com/apache/hudi/releases
    - Hudi 1.2.0 marked latest, released 2026-05-23; announcement linked for 2026-06-07.

## Contradiction / deduplication pass

The following distinctions were explicitly preserved:

- table history/time travel != correctness;
- retention/history != backup or disaster recovery;
- expiration/VACUUM/cleaning != application rollback;
- Iceberg snapshot IDs/branches/tags != Delta log versions != Hudi timeline instants;
- Delta timestamp-based history has a documented filesystem-copy caveat and is not generalized to the other formats;
- Hudi cleaning != timeline archival;
- Hudi incremental queries != CDC before/after-image semantics;
- Iceberg branch-head schema semantics != concrete snapshot schema semantics;
- existing DVC/lakeFS/OpenLineage coverage in `data-versioning-lineage.md` was not duplicated.

No performance-ranking claim was added because no independent workload-specific benchmark was needed or validated for this lifecycle baseline.
