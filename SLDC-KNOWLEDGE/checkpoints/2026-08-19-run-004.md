## Evidence-supported findings added

1. The language-agnostic categories do transfer across ecosystems, but the concrete integration surfaces differ: TypeScript has compiler/language-service separation; JVM has JDK/JUnit layers; C/C++ semantic tools rely strongly on real compile commands; .NET integrates analyzers/formatter/test execution into the SDK/CLI.
2. Product domains require additional verification surfaces rather than replacement of the generic baseline: Android adds variants/device/instrumentation/profiling; embedded adds board/emulator/HIL evidence; ML adds workload/hardware-sensitive profiler evidence; games add engine/frame/performance evidence.
3. Android documentation explicitly recommends running lint in CI because lint is not automatically executed as part of every build.
4. Zephyr documentation explicitly warns that Twister's default coverage cannot guarantee success in the full build environment; this caveat is preserved instead of treating a partial board/test matrix as universal proof.
5. clang-tidy documentation explicitly warns that diff-only reporting may miss diagnostics triggered outside changed lines; full-project/affected-file analysis remains a stronger merge/release gate.
6. Node.js 26.7.0 documents the built-in `node:test` runner as stable and gives failed test runs non-zero process status, making it suitable as a deterministic automation gate.
7. Current JUnit documentation resolved to JUnit 6.1.3 and documents Java 17+ runtime requirement for JUnit itself.
