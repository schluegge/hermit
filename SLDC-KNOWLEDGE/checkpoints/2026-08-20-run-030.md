## Primary evidence inspected

All sources below were verified on 2026-08-20.

### Ubuntu Core 26 / release lifecycle

- Official Canonical Ubuntu Core release notes:
  https://documentation.ubuntu.com/core/reference/release-notes/
- Ubuntu Core 26 overview:
  https://documentation.ubuntu.com/core/uc26/
- CVE remediation / revision semantics:
  https://documentation.ubuntu.com/core/explanation/cve-remediation/

Verified:
- Ubuntu Core 26 release date is 2026-05-14.
- snaps refresh automatically on running Ubuntu Core systems;
- base/kernel refreshes can require reboot;
- snap revision is a distribution-artifact identity distinct from the informational version field.

### Refresh governance / validation sets

- Refresh control:
  https://documentation.ubuntu.com/core/explanation/refresh-control/
- Validation sets explanation:
  https://snapcraft.io/docs/explanation/how-snaps-work/validation-sets/
- Validation-set management:
  https://snapcraft.io/docs/how-to-guides/manage-snaps/manage-validation-sets/
- Model assertion reference:
  https://documentation.ubuntu.com/core/reference/assertions/model/

Verified:
- validation sets can constrain required/optional/invalid snaps and exact revisions;
- monitor mode is not enforcement;
- enforcement has documented bypasses;
- production sequence handling matters for rollback/recovery;
- validation sets do not make breaking hard dependencies safe during transient multi-snap transitions.

### Essential-snap/model evolution

- Remodel essential snaps:
  https://documentation.ubuntu.com/core/explanation/remodel-essential-snaps/
- Remodeling:
  https://documentation.ubuntu.com/core/explanation/remodeling/

Verified:
- candidate essential base/kernel changes are staged and tested through reboot;
- failed boot verification cancels the remodel and undoes changes up to that point;
- the new recovery system is separately verified;
- remodel does not support base downgrade.

### Revert and recovery

- Snap update/revert behavior:
  https://snapcraft.io/docs/how-to-guides/manage-snaps/manage-updates/
- Ubuntu Core recovery modes:
  https://documentation.ubuntu.com/core/explanation/recovery-modes/

Verified:
- `snap revert` can restore an earlier retained revision and associated snap configuration/system data;
- common user/application data may not be reverted;
- recover, factory-reset and reinstall/install modes have different data effects.

## Contradiction / deduplication pass

The following false equivalences were explicitly rejected:

- Ubuntu Core refresh/remodel != rpm-ostree deployment switch.
- Ubuntu Core refresh/remodel != bootc image switch.
- Ubuntu Core refresh/remodel != NixOS generation switch.
- snap revision != user-facing version.
- validation-set compliance != application correctness.
- successful boot verification != service/SLO correctness.
- `snap revert` != complete user-data rollback.
- recover mode != factory reset != reinstall.
- authenticated model/assertion != functional correctness.
